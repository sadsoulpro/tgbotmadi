# «Точка опоры» — Telegram-бот диагностики

Готовый блок из семи аудио по ТЗ. После него бот показывает персональный результат, а после нажатия «Продолжить» — ссылку на личный разбор. Номер можно оставить по желанию после открытия предложения о записи. Если следующая часть ещё не добавлена, бот честно сообщает, что продолжение готовится. Данные, медиа, тексты и настройки хранятся локально у владельца.

Для VPS с уже работающим сайтом см. [инструкцию развёртывания](deploy/README.md). Контейнер бота не занимает публичные порты 80/443.

## Запуск на Windows

1. Создайте Telegram-бота через BotFather и скопируйте токен.
2. Установите Python 3.12 или новее.
3. В PowerShell, находясь в этой папке:

   ```powershell
   py -3.12 -m venv .venv
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   if (-not (Test-Path .env)) { Copy-Item .env.example .env }
   ```

4. При первой установке заполните `.env`: `BOT_TOKEN`, уникальный `ADMIN_PASSWORD` длиной не менее 12 символов, при наличии — `BOOKING_URL` и `CONTACT_URL`. Можно использовать запоминающуюся фразу из нескольких слов, разделённых дефисами. Ссылки должны начинаться с `https://`. В этой рабочей папке токен и пароль уже настроены. `.env` исключён из Git.
5. Запустите:

   ```powershell
   .\.venv\Scripts\python.exe -m app.main
   ```

   Для фонового запуска используйте `.\start.ps1`, для остановки — `.\stop.ps1`. Логи: `data/bot.stderr.log` и `data/bot.stdout.log`.

6. Откройте `http://127.0.0.1:8080/admin` на том же компьютере. Логин по умолчанию — `owner`, пароль — из `.env`.

Для непрерывной работы компьютер/сервер должен быть включён. Для удалённого доступа к админке используйте HTTPS через обратный прокси; стандартная конфигурация слушает только локальный адрес. Не запускайте второй экземпляр бота с тем же токеном одновременно.

Токен предоставлен владельцем и уже внесён в локальный `.env`. Для проверки связи без запуска бота выполните `.\.venv\Scripts\python.exe -m app.check_connection`. Пароль админки сгенерирован и находится в строке `ADMIN_PASSWORD` файла `.env`.

## Что настроить перед публикацией ссылки

- В админке откройте **Части** и проверьте семь аудио и две карточки. Начальные файлы уже привязаны к частям. У частей 2 и 4 в исходной папке лежат дубли; по умолчанию выбран файл, наиболее близкий к названию из ТЗ.
- В **Настройках** при необходимости укажите `booking_url` и `contact_url`. Для записи по умолчанию используется `https://madirahman.com/bio`; прежнее временное значение `https://madirahman.com/` при запуске заменяется на эту страницу. Другая ссылка в админке имеет приоритет над `.env`, а ссылка из `.env` — над значением по умолчанию.
- На работающем сервере 04.10.2026 обе ссылки временно направлены на `https://madirahman.com/` по решению владельца. После появления страницы бронирования и прямого контакта замените каждое поле отдельно. Бот учитывает запрос ссылки, но главная страница сайта не подтверждает фактическую запись.
- В разделе **Лид-магниты** при первом запуске автоматически появляются пять чек-листов заказчика: `checklist_udobniy`, `checklist_rebenok`, `checklist_avtomat`, `checklist_gnev`, `checklist_odin`. Их приветствия и фразы-переходы можно редактировать без разработчика. Бот отправляет приветствие, PDF, фразу-переход и затем общее приветствие с одной кнопкой «Начать». Для неизвестного тега или входа без тега — только общее приветствие. Повторный вход с другим тегом выдаёт его файл, но сохраняет шаг и оценки. Существующие настройки тегов при обновлении не перезаписываются.
- В **Текстах** отредактируйте формулировки. Приветствие из PDF внесено с уточнённой по MP3 длительностью. Сохраняйте переменные в фигурных скобках.
- В приветствии диапазон длительности уточнён по самим MP3: некоторые записи короче 4 минут, одна длится около 9 минут 28 секунд. Текущий текст сообщает «примерно от трёх до десяти минут».
- Пока username бота — `@madirhmnbot`. Готовые ссылки: `https://t.me/madirhmnbot?start=checklist_udobniy`, `https://t.me/madirhmnbot?start=checklist_rebenok`, `https://t.me/madirhmnbot?start=checklist_avtomat`, `https://t.me/madirhmnbot?start=checklist_gnev`, `https://t.me/madirhmnbot?start=checklist_odin`. Старые метки вроде `inerciya` продолжают работать как источники аналитики, но без отдельного PDF, пока их не настроят в админке.
- Отображаемое имя действующего `@madirhmnbot` установлено как «Точка опоры» через Telegram Bot API. Его можно повторно проверить/установить командой `python -m scripts.set_bot_name --expect-username madirhmnbot` с токеном в `.env`. Username остаётся прежним. После будущей смены username владельцем обновите публичные ссылки и встроенные ссылки в PDF. На компьютере с исходными PDF установите `pypdf` (`py -m pip install pypdf`) и выполните `py scripts/prepare_checklists.py "ПАПКА_С_ИСХОДНЫМИ_PDF" assets/lead_magnets --username НОВЫЙ_USERNAME`. Затем отправьте обновлённые PDF в Git и пересоберите контейнер на сервере.

## Поведение

- Повторный `/start` оставляет шаг и оценки, показывает общее приветствие с одной кнопкой, а при настроенном теге сначала выдаёт соответствующий материал. `/continue` возвращает к текущему шагу. `/restart` начинает новое прохождение, сохраняя прежний результат. После третьего аудио остаётся только штатная кнопка перехода к четвёртой части; отдельную кнопку или предложение не добавляли по просьбе заказчика.
- Оценки 0–10 ставятся кнопками после частей 4–7. Сначала бот показывает только персональный итог с кнопками **Изменить оценку** и **Продолжить**. После нажатия **Продолжить** приходят объяснение, информация о дальнейших частях и кнопка **Хочу личный разбор**. Защитный текст при низких оценках сохраняется; предложение разбора теперь доступно и в этом варианте.
- После нажатия **Хочу личный разбор** бот сразу присылает ссылку на форму записи. Под ней есть необязательная кнопка **Оставить номер** с запросом собственного контакта через Telegram. После отправки номера бот подтверждает, что автор напишет в течение двух дней. При наличии следующих частей запрос номера может повториться один раз ближе к концу серии, если контакт не оставлен.
- Напоминания отправляются через 24 часа и через 3 дня без действия пользователя. Всего не более двух напоминаний на пользователя; возвращение в бот не увеличивает этот лимит.
- В админке доступны воронка, источники, распределение оценок, список пользователей, CSV по таблицам и полная SQLite-копия. На каждом шаге фиксируются два события: материал отправлен и человек нажал переход дальше. Разница показывает отвал, но Telegram не сообщает, слушал ли человек аудио. Для повторных тегов таблица лид-магнитов считает уникальных посетителей каждого тега, а начатое прохождение и результат относит к последнему тегу перед началом этого прохождения; ранее начатый проход не переносится в другой тег.
- В разделе **Пользователи** отображается последний известный `@username` со ссылкой на Telegram. Поиск принимает username с `@` и без него; фильтр показывает пользователей с username или без. Username входит в `users.csv`, доступный только после входа в админку. Если человек не задал username, показывается прочерк. У уже существующих пользователей поле обновится после следующего действия в боте.
- Бот видит нажатие своей кнопки «Хочу личный разбор» и выдачу ссылки, но не видит открытие внешней URL-кнопки. Подтверждённая запись — отдельное событие: сервис бронирования может отправить `POST /booking-webhook` с JSON `{"telegram_id": 123}` и заголовком `X-Booking-Secret`, если задан `BOOKING_WEBHOOK_SECRET`. Владелец может отметить запись вручную в админке только после проверки в системе бронирования.

## Продолжение серии

После седьмого аудио контент следующих частей в переданных файлах отсутствует. Пока восьмая часть не включена, кнопка «Слушать дальше» скрыта и результат сообщает, что продолжение готовится. Новые части добавляются в админке как аудио, картинка, оценка, текстовый ответ или кнопка. Они создаются выключенными; загрузите нужный файл и включите часть. Текстовые и числовые ответы сохраняются в таблице `answers` и доступны в CSV.

## Данные и бэкап

База по умолчанию — `data/bot.sqlite3`, загруженные медиа — `data/media`. Сохраните обе папки при переносе проекта. Исходные семь MP3 и две PNG лежат рядом с приложением и также должны оставаться на месте либо заменяться через админку. В админке доступна резервная копия базы. Список нажатий и время шагов находится в CSV `events.csv`.
